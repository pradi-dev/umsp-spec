# Messaging Events

Direct messages and channel messages share the same event shape (see
[Event Format](./event-format.md)), typed as `umsp.message`.

## Rich attachments

A message **MAY** carry zero or more attachments. The attachment type
relevant to the "send a webpage" experience is `link-preview`:

```json
{
  "type": "umsp.message",
  "content": {
    "body": "check this out",
    "attachments": [
      {
        "kind": "link-preview",
        "url": "https://example.com/article",
        "fetched-at": 1745395200,
        "title": "Example Article",
        "description": "...",
        "thumbnail-hash": "sha256:..."
      }
    ]
  }
}
```

A `link-preview` attachment **MUST** include `url` and `fetched-at`, and
**SHOULD** include `title`, `description`, and `thumbnail-hash` (a
reference into the media repository, see
[Media Repository](./media-repository.md)).

Homeservers **MUST NOT** fetch the `url` on behalf of the sender's peers.
Preview metadata **MUST** be generated by the sending client (or its own
homeserver, on the sender's behalf) before the message is sent — never by
the recipient's homeserver. This avoids both a server-side-request-forgery
surface and leaking recipients' access patterns to arbitrary third-party
URLs.
